# 📖 使用手册 · 麦麦成长时刻

> 5 分钟上手。所有功能都在一个网页里，按「看板 → 出发 → 等餐 → 记录」的顺序走一遍就是完整旅程。

---

## 〇、三种启动方式

| 场景 | 命令 | 说明 |
|---|---|---|
| 第一次看效果 | `python run.py web --demo` | 演示模式：内置数据 + 假订单，**不调用任何真实接口** |
| 日常使用 | `python run.py web` | 真实模式：读 `.env` 里的 Token 调麦当劳 MCP |
| 给手机用 | `python run.py web --host 0.0.0.0` | 同上，但局域网内手机可访问 |

启动后浏览器打开 `http://127.0.0.1:8000`。

## 一、第一次使用：建立档案（1 分钟）

1. 顶部导航点 **「记录」** → 右侧「我的身体档案」
   （或直接访问 `http://127.0.0.1:8000/#profile`）
2. 填身高 / 体重 / 年龄 / 活动量 / 目标（减脂、维持、增肌）→ 保存
3. 系统算出你的 BMI 和**每餐目标**：早餐 25% / 午餐 35% / 晚餐 30% / 加餐 10%

> 档案决定后面所有推荐。不改也能用，会按默认值（172cm / 65kg）推荐。

## 二、一次完整的旅程

### 第 1 步：我想去麦当劳！
- 看板页点黄色大按钮 **「我想去麦当劳！」**，进入出发屏
- 在「你在哪」填地址（如「上海市人民广场」），或点 **「获取当前位置」**
  —— 定位后会自动把坐标翻成地名填回输入框，并按它查门店
- 选步行 / 骑行 → **「查找附近门店」**
- 每家门店卡片会显示：距离、营业状态、真实路线耗时、**这一趟消耗多少 kcal**

### 第 2 步：这一餐吃什么
- 出发屏中部按时间**自动选中当前餐次**（早餐 05:00–10:30 / 午餐 10:30–14:30 /
  下午茶 14:30–17:00 / 晚餐 17:00–21:30 / 夜宵 21:30–05:00）
- 手动点过餐次按钮后不再被自动覆盖
- 系统给出最贴近你目标的 3 个组合，每项标注「热量达成 xx%」

### 第 3 步：去下单
- 挑一家门店，点它卡片上的 **「It's Time to Mc · 去这家下单」**
- 会跳转麦当劳官方渠道（默认 mcd.cn）完成下单——本项目不代下单、不碰支付
- 之后**每 2 分钟**自动查一次最新订单；出现新订单就自动把
  **通勤消耗 + 订单营养 + 等餐时长**写进成长档案（同一单只记一次）

### 第 4 步：等餐背单词
- 顶部导航点 **「等餐」**，订单面板每 5 秒刷新（取餐码 / 制作进度 / 预计时间）
- 点 **「开始背单词」**，系统按剩余时间推荐题量；答错的词明天自动回来复习
- 交卷后专注分钟按**真实计时**入库

### 第 5 步：记录
- **「我的麦当劳订单」**列表：最近 5 单（含历史订单），每单已算好营养
- 点 **「记入这一餐」** 一键入档；套餐里营养库查不到的子项会按
  「同类别 + 价格最接近」估算并标注依据
- **「本餐目标 vs 实际」**：没记录时自动用最近一单历史订单兜底展示

## 三、配置

### 麦当劳 MCP Token（必需）
项目根目录建 `.env`（参考 `.env.example`）：

```ini
MCD_MCP_TOKEN="比赛方发放的令牌"
```

### 腾讯位置服务 Key（可选）
```ini
T2M_TMAP_KEY="腾讯位置服务Key"
```
并在控制台 → 配额管理里给这把 Key 分配：**地址解析（地址转坐标）、路线规划-步行、
路线规划-骑行**（必需）；逆地址解析可选（用于把定位显示成地名）。

没有 Key 也能用：路线按「距离 × 绕行系数」估算，界面会标注「估算」。
体检脚本：`python tools/check_quota.py`。

### 环境变量速查

| 变量 | 默认 | 说明 |
|---|---|---|
| `MCD_MCP_TOKEN` | — | 麦当劳 MCP 令牌 |
| `T2M_TMAP_KEY` | — | 腾讯位置服务 Key |
| `T2M_TMAP_MAX_PER_SEC` | 1 | 地图每秒调用上限 |
| `T2M_TMAP_MAX_PER_DAY` | 100 | 地图每日调用上限 |
| `T2M_ORDER_URL` | https://mcd.cn/ | 下单跳转地址 |
| `T2M_DB` | data/records.db | 成长档案数据库路径 |

## 四、手机端

1. 电脑：`python run.py web --host 0.0.0.0 --port 8000`（启动时会直接打印手机该访问的地址）
2. 手机连同一 Wi-Fi，浏览器打开 `http://<电脑IP>:8000`
3. 可以「添加到主屏幕」当 App 用；界面已做移动端适配

查电脑 IP：不用手动查——记录屏的「手机 ↔ 电脑同步」面板会显示当前局域网地址。

### 手机带出门（离线同步）

手机是要带着去麦当劳的，一出 Wi-Fi 就连不上电脑。项目为此做了三层保障：

1. **在家即同步**：同一 Wi-Fi 下手机写的就是电脑的数据库，无需任何操作；
2. **出门照常玩**：断网后页面照样能打开（离线壳 + 词库缓存在手机里），
   背单词、记一餐、记通勤会先排进手机的待发队列（顶栏显示「待同步 N 条」）；
3. **回家自动补传**：连回 Wi-Fi 打开页面，攒下的记录自动传回电脑。
   每条记录带 uid，重复上传只落一次，卡路里/单词数不会被算两遍。

万一两台设备物理上见不到面：记录屏「导出备份 JSON」→ 微信/QQ 传到电脑 →
「导入备份」，同样是按 uid 幂等合并，不会重复。

## 五、常见问题

**Q：背单词词库能换吗？**
能。`tools/seed_words.py` 支持 CET-4 外的自定义词表，往 `words` 表里插即可。

**Q：等餐时必须背单词吗？**
不是。等餐时长会自动计成「专注时间」，但背单词的收益（词数、正确率）只有玩了才有。

**Q：我的身体数据会上传吗？**
不会。身高体重、成长记录全在本地 `data/records.db`；定位坐标只在本机参与路线计算。

**Q：订单怎么对不上？**
订单数据来自麦当劳 MCP 的 `order-list` / `query-order`，以官方小程序为准；
本项目只读不写，不会影响你的订单。

**Q：演示模式会不会泄露我的真实订单？**
不会。`--demo` 连 MCP 都走假数据（T2M_MOCK=1），投屏安全。

**Q：手机上的记录会丢吗？**
断网时记录先存在手机浏览器的 localStorage 里（关闭浏览器也在），
连回 Wi-Fi 后自动补传；补传成功前不会删除，失败会留在队列里下次再试。
换手机/清浏览器数据前，先用「导出备份 JSON」把记录带出来。
